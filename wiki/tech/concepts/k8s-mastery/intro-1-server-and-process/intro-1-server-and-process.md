# 入門第一章：一台伺服器裡到底發生什麼事

在談容器、談 K8s 之前，得先把一件更基本的事講清楚：**當你的程式「跑起來」的時候，電腦裡發生了什麼？** 這一章不出現任何 K8s 的名詞，但後面所有東西都建立在這一章的概念上。

## 程式與程序：檔案，跟活著的東西

你的硬碟上有一個 `app.exe` 或 `app.py`。這時候它只是一個檔案，就像一本食譜——上面寫著步驟，但沒有人在煮。

當你雙擊它、或在終端機打指令執行它，作業系統會做幾件事：把檔案內容讀進記憶體、配一塊記憶體給它用、給它一個編號、然後讓 CPU 開始執行裡面的指令。這個「活著、正在執行」的東西叫做**程序（process）**。食譜變成了正在爐子上煮的一鍋菜。

這個區分很重要，因為後面很多概念都靠它：

- 同一個程式可以同時跑成很多個程序（你可以開三個瀏覽器視窗）
- 程序會佔用資源（記憶體、CPU），程式檔案不會
- 程序可以被「殺掉」，程式檔案還在
- 程序有狀態（它記得使用者登入了沒），程式檔案沒有

在你自己的電腦上看一眼現在有哪些程序：

```powershell
Get-Process | Select-Object -First 20 Id, ProcessName, WorkingSet
```

`Id` 是那個編號（PID，process ID），`WorkingSet` 是它現在佔用的記憶體。你會看到幾百個程序在跑——這台電腦上大部分東西你根本沒注意到它們的存在。

**這裡就有第一個之後會用到的概念**：作業系統負責分配 CPU 時間與記憶體給這幾百個程序，並且防止它們互相干擾。這個「分配資源、彼此隔離」的職責，等一下你會在容器那裡再看到一次，只是規模更大。

## 什麼是「伺服器」

初學時最容易誤會的一件事：以為伺服器是某種特別的機器。

其實不是。伺服器是一個**角色**，不是一種硬體。任何一台電腦，只要它「一直開著，等著別人來跟它要東西」，它就是伺服器。你現在用的筆電，只要跑一個等待連線的程式，它立刻就是一台伺服器。

不信的話，現在就做一次。在任一個資料夾底下執行：

```powershell
python -m http.server 8000
```

（沒裝 Python 的話先跳過，第五章會有不需要 Python 的版本。）

然後打開瀏覽器輸入 `http://localhost:8000`，你會看到那個資料夾的檔案列表。**你剛剛把自己的電腦變成了一台網頁伺服器。**

那真正的伺服器機器跟你的筆電差在哪？差在**取捨不同**：它通常沒有螢幕鍵盤（沒人坐在前面）、放在有穩定電力與網路的機房、硬體選的是耐久跑而不是輕薄、而且會一直開著不關機。但本質上跑的還是同一件事——一個等待請求的程序。

## Port：一台機器，很多扇門

上面那個指令裡有個 `8000`，這是**port（連接埠）**。

想像一棟公寓大樓。整棟大樓有一個地址（這就是 IP 位址，下一章會講），但裡面有很多戶，每戶有自己的門牌號碼。快遞要送到「某某路 100 號的 8000 室」，光有地址不夠，還要有房號。

port 就是房號。一台電腦有一個 IP，但可以同時跑很多個等待連線的程式，每個佔用不同的 port：

| port | 慣例上是誰 |
| --- | --- |
| 22 | SSH（遠端登入） |
| 80 | HTTP（沒加密的網頁） |
| 443 | HTTPS（加密的網頁） |
| 3306 | MySQL |
| 5432 | PostgreSQL |
| 6379 | Redis |
| 8080 / 3000 / 5000 | 開發時常用的網頁服務 |

這些號碼是**慣例**，不是規定。你完全可以讓網頁服務跑在 9999，只是別人要連的時候必須知道。1024 以下的 port 在 Linux 上需要管理員權限才能使用，這個細節之後在容器安全設定時會再遇到。

一個關鍵規則：**同一台機器上，同一個 port 同時只能有一個程序佔用**。這就是為什麼你有時會看到「port already in use」的錯誤——有另一個程式先佔走了。

看看你的電腦上哪些 port 被佔用了：

```powershell
Get-NetTCPConnection -State Listen | Select-Object LocalAddress, LocalPort, OwningProcess | Sort-Object LocalPort
```

`Listen` 狀態的意思就是「有程序在這個 port 等著」。想知道是誰佔的，拿 `OwningProcess` 去對：

```powershell
Get-Process -Id <上面看到的號碼>
```

**這個「一個 port 只能一個程序」的規則，是後面很多設計的原因。** 一台機器上要跑十個服務，就得配十個不同的 port，然後有人要記住誰是誰——這種手工管理在規模變大之後會失控，而那正是 K8s 在解決的問題之一。

## 讓程式一直活著：服務與常駐

你剛剛跑的那個 `python -m http.server`，只要你關掉終端機視窗，它就死了。這對正式服務顯然不行。

正式環境要的是：開機自動啟動、當掉自動重啟、不需要有人登入就能跑。Linux 上做這件事的東西叫 **systemd**，被它管理的程式叫**服務（service）**或**常駐程式（daemon）**。你會看到很多程式名稱結尾有 `d`（`sshd`、`dockerd`、`containerd`），那個 d 就是 daemon。

概念上 systemd 做的事情是：

1. 開機時按順序啟動一批程式
2. 盯著它們，掛了就重啟
3. 收集它們的輸出（日誌）
4. 提供統一的操作介面（啟動、停止、查狀態）

**記住這四件事**，因為 K8s 對容器做的事情幾乎一模一樣，只是範圍從「一台機器」擴大到「一整批機器」。你之後會看到 kubelet 在單機上扮演類似 systemd 的角色。

## 「在我電腦上跑得好好的」

現在來看第一個真正的問題。

你的程式在自己電腦上跑得很好，交給同事或部署到伺服器上就爆炸。原因幾乎總是**環境不一樣**：

- 你的 Python 是 3.12，伺服器上是 3.8，某個語法不支援
- 你裝了某個系統套件，伺服器上沒有
- 你的設定檔路徑是 `C:\config`，Linux 上根本沒有這種路徑
- 你的環境變數裡有資料庫密碼，伺服器上沒設
- 你是 Windows，伺服器是 Linux，換行字元、檔名大小寫、路徑分隔符號全都不同

傳統解法是寫一份「安裝步驟文件」，讓伺服器上的環境盡量跟你的一樣。這個方法的問題是它**依賴人準確地執行**，而人會漏步驟、文件會過期、不同的伺服器會慢慢長歪。你可能聽過「那台機器只有老王知道怎麼裝」——那就是這個方法的終局。

容器要解決的就是這件事：**把程式跟它需要的整個環境打包在一起**，讓「在我電腦上」跟「在伺服器上」變成同一個東西。第五章你會親手做一次，正文第 0 章會講它在作業系統層面怎麼辦到的。

## 為什麼需要不只一台機器

假設環境問題解決了，程式在伺服器上跑得很順。接下來會遇到兩個新問題。

**第一個是容量。** 一台機器能處理的請求量有上限。使用者變多，你要嘛換更強的機器（垂直擴展，但總有天花板，而且很貴），要嘛多開幾台一起分擔（水平擴展）。多開幾台之後，馬上有新問題：使用者連進來的時候，要連到哪一台？這需要一個「分派員」，也就是**負載平衡器（load balancer）**。

**第二個是故障。** 一台機器一定會壞——硬碟壞、電源壞、網路斷、機房停電。只有一台的話，它壞了服務就沒了。所以正式服務至少要兩台，而且最好不在同一個機櫃、同一個機房。

於是你的系統從「一台機器跑一個程式」變成「好幾台機器，每台跑好幾個程式，前面有分派員，還要有人盯著誰掛了要補上」。

**這一段就是 Kubernetes 存在的理由。** 當機器有幾十台、程式有幾百個，你不可能靠人記住誰在哪、誰掛了、誰該擴容。你需要一個系統，讓你只要說「我要三份這個服務一直活著」，剩下的它自己處理。

## 「部署」到底是什麼

現在可以回答一個入門者常常說不清楚的問題：部署（deploy）到底在做什麼？

它其實是四件事的合稱：

| 步驟 | 在做什麼 | 沒做好的症狀 |
| --- | --- | --- |
| **1. 把東西送過去** | 程式碼或打包好的成品傳到目標機器 | 版本不對、傳了一半 |
| **2. 讓它跑起來** | 在正確的環境裡啟動，帶上正確的設定 | 缺套件、缺環境變數、port 被佔 |
| **3. 讓別人找得到它** | 設定網址、port、負載平衡 | 服務活著但沒人連得到 |
| **4. 讓它一直活著** | 掛了重啟、量大擴容、更新時不中斷 | 半夜掛掉沒人知道 |

手動做這四件事是可行的——很多團隊就是這樣做的。問題出在**規模**與**重複性**：一個服務手動做還好，三十個服務、每天部署好幾次、還要保證半夜有人接，就撐不住了。

從這個角度看，後面所有工具都在自動化這四步的某一部分：

- **Docker**（容器）解決第 1、2 步：把程式與環境一起打包，換台機器結果一樣
- **Kubernetes** 解決第 3、4 步：自動分派流量、自動重啟、自動擴縮、更新時不中斷
- **CI/CD**（GitHub Actions 那類）把四步串起來自動觸發
- **監控**（Prometheus、ELK）告訴你這四步有沒有出問題

這張對照表值得記住。之後每學一個新工具，先問「它負責這四步的哪一步」，你就不會迷失在名詞裡。

## 本章回顧

- **程序**是活著的程式；程式檔案只是食譜，程序才是那鍋菜
- **伺服器**是角色不是硬體——一直開著等別人來要東西的電腦就是伺服器
- **port** 是同一台機器上的房號，同一個 port 同時只能一個程序佔用
- **服務／daemon** 是被系統管理、會自動啟動與重啟的程式
- 「在我電腦上跑得好好的」的根因是**環境差異**，這是容器要解決的
- 需要多台機器的理由是**容量**與**故障**，這是 K8s 要解決的
- **部署 = 送過去 + 跑起來 + 找得到 + 活著**，每個工具負責其中一部分
