# 入門篇：從這裡開始

如果你翻開第 0 章看到「namespace、cgroup、OverlayFS」就想關掉，那你來對地方了——**你沒有問題，是那本書從第二階開始爬**。

這套教材的正文預設讀者已經會用 Docker、看過 K8s 的 YAML、至少部署過一次東西。對很多人來說這個預設是成立的，但如果你是第一次接觸伺服器、第一次聽到「容器」、或者只寫過在自己電腦上跑起來的程式，那中間缺了一整段台階。入門篇就是那段台階。

## 這篇是寫給誰的

寫給下面任何一種狀況的你：

- 會寫程式，但程式一直都是在自己電腦上跑，沒真的「上線」過
- 聽過 Docker 和 K8s，但說不出它們解決了什麼問題
- 看到終端機的黑底白字就緊張
- 看得懂 YAML 長什麼樣，但自己寫就會出錯，而且不知道錯在哪
- 別人說「你去看一下 Pod 的 log」，你不確定那是什麼意思

**不需要**任何 Linux、網路、容器的先備知識。需要的只有：一台可以裝軟體的電腦，以及願意把指令實際打一遍的耐心。

## 為什麼要有這一段

學基礎設施跟學程式語言不一樣。學程式語言，你可以邊寫邊學，錯了馬上看到紅字。學基礎設施，很多概念是**互相依賴**的——要理解 Service 為什麼存在，得先知道什麼是 IP 和 port；要理解為什麼需要容器，得先知道「在我電腦上跑得好好的」為什麼是個問題。

跳過這些前置知識直接學 K8s，症狀通常是：你能照著教學把東西跑起來，但只要偏離教學一步就完全卡住，而且看不懂錯誤訊息在說什麼。這不是笨，是地基缺了。

入門篇的目標很具體：**讀完之後，你能自己在電腦上跑起一個 K8s、部署一個網頁服務、看得懂它壞掉時的錯誤訊息**。做到這三件事，你就有資格開始讀正文第 0 章了。

## 建議的節奏

一章抓一到兩小時，六章大約一個週末。但**不要只是讀**——這一篇裡的每個指令都設計成可以直接複製執行，你應該邊讀邊打。

打指令的時候有個習慣值得從現在養成：**先猜結果，再按 Enter**。猜對了代表你真的懂，猜錯了正好是學習的點。單純複製貼上看到「成功」，留下的東西非常少。

還有一件事：**你一定會弄壞東西，這是計畫的一部分。** 入門篇用的都是本機環境，弄壞了最壞的情況就是砍掉重來（每章都會告訴你怎麼重來）。這個階段的目標不是不出錯，而是看過夠多種錯誤，之後在正式環境遇到才不會慌。

## 讀完之後往哪走

入門篇結束時，你會在自己的電腦上有一個跑得起來的 K8s、一個部署好的服務，以及看懂錯誤訊息的能力。接下來的路徑是：

1. **正文第 0 章**（[[00-docker-foundations]]）——回頭把容器的原理補起來。這時候你已經用過容器了，讀「namespace 與 cgroup」會有實感，而不是一堆名詞
2. **正文第 1–3 章**——K8s 為什麼存在、它內部怎麼運作、YAML 的通用結構
3. **附錄 D**（[[26-lab-drills]]）——20 個「把它弄壞再修好」的實驗，這是把知識變成能力的地方
4. 之後依需要查 **附錄 C 系列**的欄位百科與 **附錄 I**（[[31-glossary]]）的術語表

一個重要的心態提醒：**不要期待第一遍就全懂**。基礎設施的知識是網狀的，很多東西要看過後面才回頭理解得了。第一遍求「知道有這個東西」，第二遍才求「知道它為什麼這樣設計」。

準備好了就從 [[intro-1-server-and-process]] 開始。
